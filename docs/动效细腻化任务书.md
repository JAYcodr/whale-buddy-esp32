| 项 | 文件 | 说明 |

| 转场接入缓动库 | `src/ui/transition.cpp` | 内联的 `1-(1-u)^3` 改为调用 `ease::outCubic`，原有转场手感不变 |

| 调用点替换 | `src/main.cpp` 486（POP_IN）、495/587/600/613（POP_OUT） | 榜单维度切换和设置页的 FADE 不变 |

**参考写法（新动效都按这个模式来）：**

```cpp
#include "ui/easing.h"
// 一次性补间：记录起始时间，每帧算进度
static uint32_t s_animStartMs = 0;
float t = ease::outCubic(ease::progress(nowMs, s_animStartMs, 140));
int16_t knobX = (int16_t)ease::lerp(offX, onX, on ? t : 1.0f - t);
// 跟随型平滑（帧率无关）：
s_shown += (s_target - s_shown) * ease::approachFactor(dtMs, 60.0f);
```

**硬规则（来自 HANDOFF.md:76-79 与上下文 §1）：**
1. 只要有补间在跑，就必须让主循环**持续出帧**：要么置对应的局部重绘标志，要么把 targetFps 拉到 60（参考 `uiAnimating`、设置页动画的做法）。补间结束后，必须回落到原来的静态帧率（10 fps），**不能让静态页常驻 60 fps 耗电**。
2. 局部重绘矩形只能覆盖动画所在区域，不能顺手改成全屏。
3. AOD、熄屏、`dimmedForNap` 期间**不播放任何新动效**，直接跳到终态。
4. 长续航档（`LONG_BATT`）下，新补间的时长保持不变，只允许帧率降低。插值都按时间算（不按帧数算），所以低帧率下只是变得不那么顺滑，不会把动画拖慢。

## 1. 任务清单（按优先级排序，每项独立提交）

### T1 去重：其余三处 easeOutCubic 改用 easing.h【必做，最先做】
- 位置：`page_rank.cpp:440`、`page_settings.cpp:191`（删掉文件内的 static 版本）、`page_tokens.cpp:141`。
- 行为不能有任何变化。验收：`tools/sim/check.sh` 的哈希基线不变。

### T2 开关（toggle）补间
- 现状：`theme.cpp:345-358` 的旋钮直接跳到端点，点行后置 `needFull`。
- 目标：旋钮位置 140 ms `outCubic`；轨道颜色在同一时间内用 `blend565` 从关色渐变到开色。
- 实现建议：`page_settings.cpp` 给每个开关行记录 `toggleAnimStartMs[row]`（或者只记最近一次切换的行号和时间，够用）。`drawToggle` 增加一个 `float t` 参数（默认 1.0，保证其他调用点不受影响）。补间期间走 `needSettingsList` 局部刷新，并要求 60 fps。
- 验收：串口 `tap` 切换开关，录屏能看到旋钮滑动过去；结束后 `stat` 显示帧率回到 10。

### T3 按下反馈淡入淡出
- 现状：`drawPressedOverlay` 按下时立即 +18% 亮度，抬起时立即恢复（`main.cpp:735-750`、`theme.cpp:442-479`）。
- 目标：按下后 60 ms 内从 0 升到 18%；抬起或取消后 120 ms 内回落到 0。强度参数通过 `blend565` 的 t 传入。
- 注意：抬起时 tap 动作往往会触发转场或全屏重绘，此时**不做回落动画**（直接被新帧覆盖）。只有“取消按下”（位移 ≥12 px）和抬起后不改变页面这两种情况才播放回落。
- 只重绘命中矩形。

### T4 滑块抓取反馈
- 现状：`page_settings.cpp:657-676,1049-1069` 的滑块没有动画，按 5% 吸附。
- 目标：(a) 抓取时旋钮半径放大到 1.25 倍，100 ms `outBack`，松手后 120 ms 恢复；(b) 显示的位置用 `approachFactor(dt, 35ms)` 跟随吸附值，避免 5% 吸附时一格一格硬跳；(c) 数值文字只在吸附值变化时更新（保持原样）。
- 落 NVS 的逻辑和时机**不要改**。

### T5 设置行展开时内容淡入
- 现状：展开 150 ms，选项要到 `frac≥0.90` 才一次性画出（`page_settings.cpp:572-578`）。
- 目标：从 `frac≥0.55` 开始画选项，前景色按 `(frac-0.55)/0.45` 用 `blend565` 从背景色渐变到正常色，同时整体从下方 6 px 上移到位。收起时反向播放。
- 注意 4-bpp 字体的抗锯齿背景色参数要传卡片色，否则会出现边缘发黑。

### T6 Token 鲸鱼选中补间
- 现状：`page_tokens.cpp:504-514` 只换颜色，而且触发的是全屏重绘。
- 目标：选中的鲸鱼在 160 ms 内颜色渐变到 `COL_ACCENT`，并做一次 `outBack` 缩放 1.0 → 1.08 → 1.0（220 ms）。之前选中的那条反向渐变回原色。改为走 `pageTokensDrawStage` 局部刷新（矩形 `(0,194,368,88)`），不再整屏重绘。

### T7 AOD 进出亮度渐变
- 现状：AOD 进出没有转场，直接整屏切换（`main.cpp:340-380`）。
- 目标：**只靠背光实现，不合成帧**：进入时先把背光在 250 ms 内降到 0 → 切到 AOD 画面 → 再在 250 ms 内升到 AOD 亮度；退出时同理（升亮可以缩短到 180 ms，让唤醒更跟手）。
- 背光接口沿用 `bright` 对象，先确认它是否支持逐帧设值，以及 I2C 或命令写入的频率上限（注意 `task_bus` 拥有 I2C，不能在 UI 线程直接操作总线，需要找现有的投递接口）。**如果这条链路改动超过约 60 行，先停下来汇报**。
- AOD 侧“别踩回去”的七条规则（`HANDOFF.md:181-189`）必须先读。

### T8 滑屏时页面圆点跟随（可选）
- 现状：水平滑动时 y<46 的区域固定使用目标帧，页面圆点直接跳到新位置。
- 目标：在 `transRun` 的 SLIDE 分支里，每帧只重绘圆点所在的小矩形，让高亮圆点的 x 坐标按 `ease` 在新旧位置之间插值（胶囊宽度可以先拉长再收回，效果类似 iOS 的页面指示器）。
- 需要从 `drawPagePills`（`theme.h:292`）提取一个“只画圆点”的函数，并通过回调或参数传给 `transRun`。如果做下来发现改动面过大，**可以跳过这一项**。

### T9 滑屏曲线微调（最后做，需要用户实机确认）
- 现在用的是 180 ms `outCubic`。这一项只提供**一个编译期开关**用于对比：`NOVA_SLIDE_EASE_QUART`（200 ms `outQuart`）。默认保持现状，不要私自修改默认值，让用户烧录两版后自己选。

### 明确不做
- 跟手拖动切页（手指拖着页面走）：需要在手势进行中合成双帧，会牵动输入状态机和转场缓冲区的生命周期，改动面大，本轮不做。
- Nova 帧动画、粒子和挤压回弹：现状已经足够细腻，不动。
- 榜单和设置页的惯性参数：刚重构完（`84a2746`），不动。

## 2. 验收与提交

每完成一项：
1. 先跑 `./tools/pio.sh run -e waveshare-esp32s3-touch-amoled-1-8`，编译必须零新增 warning；再跑 `bash tools/check_all.sh`，必须全部通过。T1 之外的任务如果改变了模拟器帧，需要用 `tools/sim/check.sh --update` 更新基线，并在提交信息里说明原因。
2. 烧录到实机，用串口命令 `{"cmd":"stat"}` 确认：动画期间 fps ≥55（USB 供电），动画结束后 3 秒内回到静态帧率；首页 `pushUs` 不劣化（基线 10.5 ms）。
3. 涉及视觉变化的任务，用 `tools/usb_shot.py` 截图（或用手机录屏）放进 `docs/previews/motion/`。
4. 提交到 `feature/motion-polish` 分支，**每项单独一个 commit**。提交身份请用 `git -c user.name=gemini -c user.email=gemini@agent.com commit ...`（禁止使用用户本人的身份），提交信息按规范写成中文 `[新增] … 原因 … 影响 …`。
5. 全部做完后，在 README 的“核心特性”里补一句动效说明，并在 HANDOFF.md 的动效条目中追加新参数表（时长、曲线、刷新矩形）。

## 3. 回滚
每项都是独立 commit，出问题直接 `git revert <sha>`。T7 涉及背光和 AOD，单独 revert 后需要实机确认 AOD 仍能正常进入和退出。
