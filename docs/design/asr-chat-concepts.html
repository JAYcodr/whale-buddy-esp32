四轴设计对比

4-AXIS COMPARISON
维度 方案 A · 诺瓦字幕舞台 方案 B · 独立对话流 方案 C · 全局对讲浮层
概念 桌面宠物提词器：把语音对话直接变成诺瓦主舞台的实时字幕与光环互动。 微型语音终端页：在 5 页圆环外独立开第 6 页，承接连续多轮指令与历史回溯。 全局对讲机模态卡：对齐 page_approval 弹窗语法，随时呼出、说完即走。
内容组织 172px 诺瓦舞台 + 单轮大字幕卡（可切最近 2 轮）+ 底部全宽 PTT 键。 顶栏对象切换/麦健康点 + 86% 宽无头像消息流 + 快捷芯片 + 底部 PTT。 底层页面压暗透视 + 模态浮层内「对讲 / 收音自测」双标签 + 简短答复卡。
交互模型 在主屏直接按住说话，无需跳页；适合“问一句、听一句”的轻量桌面交互。 支持上下拖拽翻历史、点气泡重播 TTS；松手先停 1.5s 确认草稿防误发。 任意页面长按 KEY1 或点顶栏麦克风呼出；不说话时零占位；自测支持 3s 采样+回放。
视觉语法 青/紫/薄荷三色环形声波光环环绕诺瓦，角色与语音态情绪合二为一。 气泡边框区分 DSH（青）与诺瓦（薄荷），高信息可读性（16.5px 字号）。 粗粒度 16 柱垂直频谱 + 72px 圆形物理感按键，直接兼容审批弹窗动效。
麦克风容错 右上角实时 dB 徽章 + 可展开 12 段 SNR 诊断条，收音过轻立即标红。 顶栏红点告警 + 1.5s 取消重说缓冲，能有效拦截识别错字导致的误操作。 直接内置「收音自测」模式（Peak / 底噪 / SNR / 削波% + 本机回放），最适合摸底阶段。
固件改造量 低 复用 animPage 局部脏矩形与现成 .nva。 中 需新增 page_chat.cpp、PSRAM 队列与拖拽滚动。 低 复用 POP_IN/OUT 浮层框架，甚至无需改页面环。
03

配套技术落地方案（从零风险测麦到云端识别）

ENGINEERING ROADMAP
STEP 0 · 先摸底硬件麦质
ES8311 RX 回环 + USB 导 WAV 实测

板卡已接好 PIN_I2S_DI=10（见 board_waveshare_esp32s3_touch_amoled_1_8.h），当前 src/hw/audio.cpp 仅安装了 I2S_MODE_TX 且关着 ADC。先不接聊天 UI，花最小代价做一次硬件体检：

  • 改为 I2S_MODE_MASTER | I2S_MODE_TX | I2S_MODE_RX 并开启 ES8311 MIC 通路与 PGA 增益调节。
  • 加一条串口调试命令 {"cmd":"mic_test","sec":5}：录 5 秒 16kHz/16bit 单声道 PCM 进 PSRAM（仅 ~160 KB）。
  • 端侧直接计算峰值/底噪/SNR，通过 PIN_PA_CTRL=46 喇叭回放听人声/底噪，同时串口导出 WAV 丢进你现成云端 ASR 实测 30cm / 60cm / 1m 真实字错率。
STEP 1 · 云端识别链路
推荐走局域网 host-plugin 中转

既然你已有现成云端 ASR，优先推荐 ESP32 → 局域网 host-plugin → 云端 ASR → DSH / 回复，而非 ESP32 直接建 HTTPS/WSS 连公网云端：

  • 省 RAM & 零密钥上板：避开 ESP32 端侧多路 TLS 握手内存开销，API Key/Token 全留宿主机 host-plugin。
  • 复用现有编解码：上行可走 HTTP 分块流或 WebSocket 传 16kHz PCM / 4-bit IMA-ADPCM（adpcm.js 已有同款 NVAD 格式）；下行继续复用现有 TTS（注意 applyTtsChunk 单条 98304B / ~40 汉字上限）。
  • 备选直连：若脱离电脑独立走 Wi-Fi，再退回 ESP32 直连云端网关（需要处理 TLS 证书与唤醒鉴权）。
STEP 2 · 触发与双工策略
半双工 PTT 起步，先避开无 AEC 深坑

在 ES8311 麦克风与腔体声学耦合尚未标定前，切忌一上来做全双工或常驻唤醒词（Wake Word）：

  • 按键/触屏 PTT 先行：按住屏幕按钮或物理 KEY1（当前短按回主屏、长按 800ms 进设置）开始录音，松手即止。
  • 天然无回声：开始收音时拉低 PIN_PA_CTRL 静音功放，播报 TTS 时停止采集，完全不需要吃算力的软件 AEC。
  • 推荐组合：若先验证麦质 + 快速可用，方案 C（全局对讲浮层）直接自带自测与回放闭环；定型后可按需留作全局入口，或再补 方案 A / B 的常驻界面。
